Objectif du TP

Le but de ce TP est de mettre en pratique les principes SOLID, qui sont des piliers de la conception orientée objet visant à rendre le logiciel plus robuste, maintenable et évolutif. Voici ma compréhension de ces principes basée sur le support de cours:


Ce que j'ai compris des principes SOLID

1. Single Responsibility Principle (SRP): Une classe ne doit avoir qu'une seule responsabilité et donc une seule raison de changer. Séparer les responsabilités permet de réduire le couplage et d'améliorer la lisibilité et la maintenabilité du code.

2. Open/Closed Principle (OCP): Les entités logicielles doivent être ouvertes à l'extension mais fermées à la modification. L'ajout de nouvelles fonctionnalités doit se faire par extension (interfaces, polymorphisme) sans modifier le code existant.

3. Liskov Substitution Principle (LSP): Toute classe dérivée doit pouvoir être substituée à sa classe de base sans modifier le comportement attendu du programme. Un mauvais usage de l'héritage peut entraîner des comportements inattendus.

4. Interface Segregation Principle (ISP): Il vaut mieux avoir plusieurs interfaces spécifiques qu'une seule interface générale. Une classe ne doit pas être forcée d'implémenter des méthodes qu'elle n'utilise pas

5. Dependency Inversion Principle (DIP): Les modules de haut niveau ne doivent pas dépendre de modules de bas niveau, mais d'abstractions. Cela réduit le couplage et facilite les évolutions et les tests
